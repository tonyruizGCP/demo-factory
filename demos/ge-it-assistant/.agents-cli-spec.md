# Agent Spec: Gemini Enterprise IT Assistant (`ge-it-assistant`)

## Overview
An end-to-end **Enterprise IT & Operations Assistant** built with **Google ADK 2.0** (`google-adk >= 2.0.0`) and scaffolded with `agents-cli` for **Acme Co.** (`acme-enterprise-demo`). The agent connects to the enterprise connectors and data stores bound to Gemini Enterprise app **`acme_ge_app`** (`projects/acme-enterprise-demo/locations/global/collections/default_collection/engines/acme_ge_app`).

Following the [VeerMuchandi `ge_datastore_accessor_agent`](https://github.com/VeerMuchandi/Learn_ADK_Agents/tree/main/ge_datastore_accessor_agent) blueprint, the agent implements a **User-Context OAuth & Connector Token Service (`DatastoreService`)** that:
1. Reads the end-user's OAuth token injected by Gemini Enterprise from `tool_context.state.get(AUTH_NAME)` or `tool_context.state.get(f"temp:{AUTH_NAME}")` in production (preserving user-level ACLs).
2. Gracefully falls back to Secret Manager / environment User OAuth refresh tokens, Application Default Credentials (ADC), and Discovery Engine `dataConnector:acquireAccessToken` for local development, automated evaluation (`agents-cli eval`), and third-party federated SaaS connectors (Jira, Salesforce, GitHub).

## Architecture & ADK 2.0 Design
We considered three architectural approaches:
1. **Option A: Monolithic Single-Agent with All Connector Tools**: Simple, but mixing 6+ distinct enterprise connectors (Jira, Drive, Gmail, Calendar, GitHub, Salesforce) into one prompt increases tool confusion.
2. **Option B (Chosen): ADK 2.0 Coordinator + Task-Mode Specialist Sub-Agents**: A root `it_assistant_coordinator` (`LlmAgent`) orchestrates specialized **ADK 2.0 `mode="task"`** sub-agents (`jira_ticket_specialist`, `workspace_it_specialist`, `devops_crm_specialist`) alongside direct fast-path tools, ensuring clean context isolation, structured `finish_task` returns, explicit per-turn token budgets (`max_output_tokens=2048`), and full compatibility with Gemini Enterprise `:streamQuery` (`streaming_agent_run_with_events`).
3. **Option C: Static Graph `Workflow(edges=...)`**: Deterministic DAG, but less flexible when a user asks compound or conversational multi-turn IT questions that span arbitrary combinations of Jira, Drive, Calendar, or Salesforce.

## Example Use Cases
1. **Jira Ticket Status & Triage**:
   - *Input*: `"What is the latest status of my Jira ticket SAM1-23, and what other high or medium priority tickets are open in project SAM1?"`
   - *Expected Output*: Queries the Jira connector, reports `SAM1-23` ("Escalation: GC5060 Electrical Wiring Installation Documentation", Status: `To Do`, Priority: `High`, Type: `Task`) and `SAM1-22` ("Integrate OAuth feature into transaction system for billing", Status: `To Do`, Priority: `Medium`), plus other `SAM1` tasks/epics (`SAM1-7` In Progress, `SAM1-10` In Review).
2. **IT Knowledge Base & Runbook Search (Google Drive)**:
   - *Input*: `"Find the technical resolution plan and executive briefing documents for the GC5060 support bottleneck in Google Drive."`
   - *Expected Output*: Searches the Google Drive datastore via `DatastoreService`, returning grounded summaries and Drive links for *GC5060 Pipeline Resolution Plan*, *GC5060 Technical Resolution & GTM Preflight Plan*, and *Executive Briefing: GC5060 Support Bottleneck & Pipeline Resolution*.
3. **IT Onboarding & Calendar Schedule Check (Google Calendar)**:
   - *Input*: `"When is my IT Laptop Setup session and 30-Day Check-in scheduled on my calendar?"`
   - *Expected Output*: Searches the Google Calendar datastore, returning event details and links for *IT Laptop Setup*, *30-Day Check-in with HR and Manager*, and *Architecture Overview*.
4. **IT Security & System Notification Audit (Gmail)**:
   - *Input*: `"Check my emails for any recent Salesforce security token updates or Jira workspace notifications."`
   - *Expected Output*: Searches the Gmail datastore, surfacing the *October Salesforce Platform Security Requirement Update*, *Your new Salesforce security token*, and *Finish creating work item SAM1-9* email threads.
5. **Cross-System Incident & Escalation Correlation (Salesforce + Jira + Drive)**:
   - *Input*: `"We have an escalation around the GC5060 generator electrical wiring. Check Salesforce cases, Jira tickets in SAM1, and Google Drive runbooks to give me a complete status summary."`
   - *Expected Output*: Correlates Salesforce Case `00001002` ("Seeking guidance on electrical wiring installation for GC5060", Status: `New`, Priority: `Low`) and `00001000`/`00001005`, Jira Ticket `SAM1-23` ("Escalation: GC5060 Electrical Wiring Installation Documentation", Status: `To Do`, Priority: `High`), and the Google Drive *GC5060 Technical Resolution & GTM Preflight Plan*.
6. **GitHub Engineering Repository & Issue Lookup**:
   - *Input*: `"Which GitHub repositories do we have for our Salesforce ADK agent and Gemini Enterprise Spark demos?"`
   - *Expected Output*: Queries the GitHub connector, returning `adk-salesforce-agent`, `ge-spark-gtm-demo`, `spark-demo-apps`, and `a2ui`.

## Tools Required
All tools are implemented in `app/tools.py` around `DatastoreService` (adapted from `VeerMuchandi/Learn_ADK_Agents/ge_datastore_accessor_agent/tools.py`):
1. `search_datastore_records(query: str, datastore_id: str, tool_context: ToolContext) -> dict`:
   - Generic Discovery Engine datastore search following the blueprint pattern (`tool_context.state.get(AUTH_NAME)` $\to$ `Bearer` token header $\to$ User OAuth / ADC fallback) against `projects/{PROJECT_ID}/locations/{DATASTORE_LOCATION}/collections/default_collection/dataStores/{datastore_id}/servingConfigs/default_search:search`.
2. `search_jira_tickets(query: str, project_key: str, tool_context: ToolContext) -> dict`:
   - Searches Jira issues/tasks/epics via Discovery Engine Jira datastore and federated Jira connector token (`{JIRA_CONNECTOR_ID}/dataConnector` $\to$ Atlassian REST API v3 JQL search) so specific ticket keys (`SAM1-23`, `SAM1-22`, `SAM1-7`, etc.) and statuses are always returned with 100% fidelity.
3. `search_it_knowledge_base(query: str, tool_context: ToolContext) -> dict`:
   - Searches the connected Google Drive datastore and Notebook datastore for IT runbooks, resolution plans, architecture reviews, and security questionnaires.
4. `search_it_emails_and_calendar(query: str, source: str, tool_context: ToolContext) -> dict`:
   - Searches the connected Gmail datastore and Google Calendar datastore for IT notifications, security alerts, and onboarding/check-in events.
5. `search_salesforce_cases(query: str, tool_context: ToolContext) -> dict`:
   - Searches Salesforce support cases and accounts via the connected Salesforce connector (`{SALESFORCE_CASE_DATASTORE_ID}` + connector token fallback to Salesforce REST API).
6. `search_github_engineering(query: str, search_type: str, tool_context: ToolContext) -> dict`:
   - Searches GitHub issues and repositories via the connected GitHub datastores and GitHub connector token.

## Constraints & Safety Rules
- **Strict Grounding (Zero Hallucination)**: Never fabricate ticket IDs, statuses, assignees, document links, or calendar times. Only report data returned by the connector tools.
- **Read-Only Default**: Do not mutate, delete, or close production tickets/cases or send external emails unless explicitly instructed and confirmed by the user.
- **User ACL & Credential Hygiene**: Never log or echo raw OAuth access tokens in user-facing responses; only log token presence (`found` vs `fallback to ADC`) in debug logs.
- **Valid Markdown**: Format all responses in clean Markdown with structured bullet points or tables showing Ticket/Case ID, Title/Summary, Status, Priority, and Source Link.

## Success Criteria
1. **Unit & Integration Tests**: `uv run pytest` passes 100% of unit and integration tests.
2. **Evaluation Suite (`agents-cli eval generate && agents-cli eval grade`)**: Evaluates a 6-case IT Assistant dataset (`tests/eval/datasets/basic-dataset.json`) covering Jira ticket status, Drive IT KB, Calendar onboarding schedule, Gmail security alerts, GitHub repos, and cross-connector incident correlation:
   - `custom_response_quality` $\ge 4.5 / 5.0$
   - `tool_invocation_check` $= 1.00$
3. **Deployment & Registration**: Deployed to Vertex AI Agent Runtime (`us-central1`) and registered to Gemini Enterprise (`acme_ge_app`) via `agents-cli publish gemini-enterprise`.
